# Web 结果隔离与聊天总结设计

## 目标

改善本机 Web 控制台的日常使用体验：

1. 每个左侧功能保留自己的结果，切换功能时不显示其他功能的旧结果。
2. 通用数据卡片中的字段名统一显示中文，布尔值显示为“是/否”。
3. 新增“聊天记录总结”，通过可搜索下拉框选择会话，通过日历选择起止日期，并提供“复制”和“复制关键信息”两种输出。
4. 本轮不修改本人邀请识别逻辑。

## 交互设计

### 功能结果隔离

结果区仍位于工作区底部，但状态按左侧功能分别保存。首次进入功能时显示该功能的空状态；执行完成后仅更新发起操作的功能结果。用户切换回来时，恢复该功能上一次的结果、复制内容和下载状态。即使请求执行期间切换菜单，也不会把异步返回结果展示到另一个功能。

### 中文字段

通用对象渲染器使用集中式字段标签表，将 `chat`、`username`、`is_group`、`unread`、`last_message`、`msg_type`、`sender`、`timestamp`、`time` 等字段转换为中文。消息类型和布尔值同样在展示层本地化。原始账号、时间戳和消息内容保持不变，避免改变底层数据。

### 聊天记录总结

左侧新增“聊天总结”。进入后自动读取最近会话，搜索框支持按会话名称或稳定账号匹配，下方下拉菜单展示匹配结果；选择时内部使用稳定账号查询，避免同名会话选错。

起止时间使用 `date` 控件，只接受天粒度。默认起止日期均为本机当天，结束日期由现有历史记录解析器自动扩展至当天 23:59:59。查询读取该范围内最多 50,000 条消息，不暴露数量和偏移等技术参数。

结果页展示会话、日期范围、消息数量和按时间整理的聊天内容。普通复制生成带总结要求、会话信息和完整记录的 AI 输入文本；复制关键信息生成紧凑的时间—发言人—内容清单。两种文本均只写入系统剪贴板，不主动上传到任何外部服务。

## 数据流

1. 浏览器通过现有 `/api/run` 调用 `sessions --limit 500 --format json`。
2. 用户搜索并选择会话，前端保存该会话稳定账号。
3. 提交后通过现有 `/api/run` 调用 `history <账号> --start-time <日期> --end-time <日期> --limit 50000 --media --format json`。
4. 前端将返回的 `message_items` 渲染为总结准备页，并分别生成完整复制文本与关键信息文本。

不新增联网接口，不改变 CLI 历史记录命令和本地数据库读取路径。

## 异常处理

- 会话列表加载失败时，在下拉框中显示可重试状态。
- 未选择会话、日期不完整或开始日期晚于结束日期时，在当前功能结果区显示中文校验提示。
- 没有聊天记录时仍生成范围摘要，但复制文本明确标记“没有记录”。
- 不可识别的字段名保持原始名称，保证新版本数据不会消失。

## 验收标准

- 在邀请统计生成结果后切换到其他功能，不再看到邀请统计内容；切回邀请统计可恢复结果。
- 最近会话截图中的九个字段标签全部中文化，`true/false` 显示为“是/否”。
- 聊天总结可打开搜索下拉、选择会话、选择日级起止日期并读取记录。
- 聊天总结结果同时提供“复制”和“复制关键信息”。
- 完整测试、Windows 冻结构建和本机浏览器验收通过。
