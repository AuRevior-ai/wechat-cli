# 群邀请统计功能设计

## 目标

为 WeChat CLI 增加群邀请统计能力，覆盖 CLI 和本地 Web 界面。工具必须扫描指定群在本地微信数据库中全部可见的系统消息，识别直接邀请和分享二维码入群事件，生成可审计的邀请关系明细，并按唯一被邀请人数从多到少排列邀请者。

首个真实验收群为“破界青年OPC销冠争霸赛🏆”，但产品代码不得硬编码该群。

## 已确认的统计口径

### 有效事件

系统识别以下两类有明确归属的入群事件：

1. 直接邀请：`"邀请者"邀请"被邀请者"加入了群聊`
2. 二维码邀请：`"被邀请者"通过扫描"分享者"分享的二维码加入群聊`

二维码分享者视为邀请者。没有分享者信息的自主扫码提示（例如“你通过扫描二维码加入群聊”）保留为来源不明事件，不进入排行榜。

一条直接邀请提示如果包含多个被邀请人，应拆分为多条邀请关系明细。

### 唯一人数与事件数

排行榜的主指标是每位邀请者的唯一被邀请人数。同一邀请者重复邀请同一个人入群，只计一个唯一被邀请人，但所有入群事件均保留在明细中，并计入该邀请者的事件数。

如果同一个被邀请人分别由两个邀请者带入，则分别记入两位邀请者，因为本地系统消息无法判断最终业务归属。

### 时间范围

默认范围是该群在当前本地消息数据库中全部可见的历史，不设置默认数量上限。CLI 和 Web 都提供可选开始、结束时间；结束日期仅填写日期时覆盖到当天 23:59:59。

## 身份模型

### 稳定身份优先

排行榜身份优先使用群成员数据库中的稳定账号标识（通常为 `wxid`），昵称只用于展示和匹配。

目标群中已确认：

- `小陶 老师` 对应 `wxid_8ncies5owakx11`
- `小陶老师 青年OPC盟主` 对应 `wxid_gd9gzapbdq8e12`

这两个账号必须始终分开统计，不能因为昵称相似而合并。

### 自动解析规则

对系统提示中的邀请者和被邀请者昵称，按以下顺序解析身份：

1. 用户提供的手动绑定，优先级最高。
2. 当前群成员的 `display_name`、`remark`、`nick_name` 完全匹配；只有全部候选最终指向同一个账号标识时才算唯一匹配。
3. 无法唯一匹配时，使用规范化后的完整历史昵称作为临时身份键，并标记 `unresolved`。

规范化只允许去除首尾空白和统一引号，不允许模糊匹配、相似度匹配、包含匹配或自动合并。

底层邀请系统消息中的 `real_sender_id` 和 `packed_info_data` 在已检查的 4.1.12.26 数据中不能稳定解析出邀请者账号：不同账号可能得到相同或空白映射。因此第一版不得把这两个字段当作稳定身份来源。

### 手动绑定

CLI 支持重复提供：

```text
--bind-identity "历史昵称=wxid_xxx"
```

Web 使用多行输入框，每行一个相同格式的绑定。绑定结果在输出中标记 `identity_source=manual`，原始昵称仍保留，便于审计。格式错误或一个历史昵称重复绑定到不同账号时必须报错。

## 数据采集与去重

核心层直接遍历该群在所有消息分库中的对应 `Msg_<hash>` 表，只查询系统消息及所需字段，不通过 CLI 文本输出二次解析。

每条候选行读取：

- 数据库来源
- `local_id`
- `server_id`
- `create_time`
- `message_content`
- 内容压缩标记

跨分库去重优先使用非零 `server_id`。`server_id` 缺失时，使用时间戳和规范化原文组成后备键；数据库路径与本地消息编号只用于诊断，不能进入跨分库后备键。解析失败不能静默跳过，应保留原文、时间和失败原因。

## 核心结果模型

核心统计函数返回一个可直接 JSON 序列化的对象：

- `chat`：群显示名
- `username`：群账号标识
- `scope`：开始时间、结束时间、首条可见系统消息时间、末条可见系统消息时间
- `summary`
  - `system_message_count`
  - `invite_event_count`
  - `attributed_event_count`
  - `unique_invitee_count`
  - `unattributed_count`
  - `unresolved_identity_count`
  - `unparsed_count`
- `ranking`：邀请者排行
- `events`：全部已解析邀请事件
- `unattributed_events`：没有可归属邀请者的事件
- `unparsed_messages`：看起来与入群有关但未能解析的系统提示
- `failures`：数据库读取失败

`summary.unique_invitee_count` 表示全部已归属事件中按稳定身份或完整历史昵称去重后的全局被邀请人数；`summary.unresolved_identity_count` 表示邀请者或被邀请者至少一方身份未解析的已解析事件数。

每个排行项包含：

- `rank`
- `inviter_key`
- `inviter_username`
- `inviter_name`
- `historical_names`
- `identity_status`
- `identity_source`
- `unique_invitee_count`
- `event_count`
- `direct_count`
- `qr_count`
- `first_invite_time`
- `last_invite_time`
- `invitees`

每个事件包含：

- `event_id`
- `server_id`
- `timestamp`
- `time`
- `method`（`direct`、`qr` 或 `unattributed_qr`）
- `inviter_name_raw`
- `inviter_username`
- `inviter_key`
- `inviter_identity_status`
- `invitee_name_raw`
- `invitee_username`
- `invitee_key`
- `invitee_identity_status`
- `raw_text`

排行按以下顺序稳定排序：

1. 唯一被邀请人数降序
2. 首次邀请时间升序
3. 邀请者展示昵称升序

同一邀请者的唯一被邀请人使用稳定账号标识去重；无法解析稳定身份时使用规范化后的完整历史昵称去重。

## CLI 设计

新增命令：

```powershell
wechat-cli invite-stats "群名"
```

选项：

- `--start-time`
- `--end-time`
- `--bind-identity`，可重复
- `--format json|text|csv`，默认 `json`
- `--output PATH`，可选；CSV 推荐写入文件

JSON 输出完整核心结果。文本输出先显示摘要和排行，再显示邀请关系明细、来源不明、身份待确认与未解析信息。CSV 每行一条邀请关系，包含邀请者排名、稳定账号、唯一拉人数、被邀请者、时间、方式和原始提示；文件编码为带 UTF-8 BOM 的 UTF-8，以便 Excel 直接打开。

传入个人聊天、找不到聊天对象、找不到消息表、绑定格式错误或输出路径不可写时返回非零退出码和明确错误。

## Web 设计

侧边栏增加“邀请统计”入口。页面表单包含：

- 群名称
- 开始时间
- 结束时间
- 历史昵称绑定多行输入框
- “生成统计”按钮

结果区域采用现有本地控制台的视觉语言，不另建独立前端框架：

1. 摘要卡片显示统计范围、总事件、已归属、来源不明、待确认身份和未解析数量。
2. 排行主表显示名次、邀请者、稳定账号、唯一拉人数、直接邀请、二维码邀请和事件总数。
3. 排行行可展开查看该邀请者的被邀请人、入群时间和方式。
4. 明细区显示全部事件；来源不明、待确认身份和未解析提示使用明确状态标签。
5. 提供“导出 CSV”按钮，浏览器生成带 UTF-8 BOM 的下载文件。

Web 安全白名单增加 `invite-stats` 命令及其允许参数，继续禁止任意命令执行。Web 调用 CLI 的 JSON 输出并使用专用渲染器，不能在浏览器中重新计算排名。

## 错误与兼容性

- 没有邀请事件时返回成功的空统计，不视为错误。
- 任一消息分库读取失败时继续处理其他分库，并在 `failures` 中报告。
- 与入群相关但模板未知的系统提示进入 `unparsed_messages`。
- 其他系统提示（撤回、改群名等）不进入未解析集合。
- 当前群成员重名导致身份不唯一时不得任选一个账号。
- 手动绑定可以解决历史改名，但不得隐式覆盖冲突绑定。
- 现有 `history`、`stats`、`members` 和 Web 功能保持兼容。

## 测试策略

采用测试驱动开发，每项生产行为先建立失败测试：

1. 直接邀请、二维码邀请、自主扫码、多人邀请和未知模板解析。
2. 事件跨分库去重。
3. 唯一被邀请人去重与事件明细保留。
4. 排行降序、并列排序和方法计数。
5. 群成员精确身份解析、相似昵称分离、重名歧义、手动绑定和绑定冲突。
6. CLI JSON、文本、CSV、时间范围、输出文件及错误返回。
7. Web 命令白名单、参数转换、页面表单和专用排行榜渲染。
8. 全量既有测试回归。

## 实机验收

使用“破界青年OPC销冠争霸赛🏆”执行：

1. 扫描全部可见系统消息。
2. 抽样核对直接邀请和二维码邀请。
3. 确认两个小陶账号按不同 wxid 分列。
4. 比较 CLI JSON、文本、CSV 和 Web 排名的一致性。
5. 确认来源不明与身份待确认记录可见。
6. 重建 Windows x64 独立 EXE 和一键安装包。
7. 使用打包后的 EXE 重跑统计，确认交付环境无需源码或 Python。

## 源码版本控制

本地源码根目录初始化为 Git 仓库。建立 `.gitignore`，排除 Python 缓存、测试缓存、构建目录、交付压缩包、运行日志、临时数据库缓存、编辑器文件和本地密钥配置。

提交顺序：

1. 提交当前已验证的 0.2.5 源码与本设计规格，作为邀请统计开发前基线。
2. 按核心统计、CLI、Web、文档与版本发布阶段分别提交。
3. 最终确认工作树干净，并保留完整提交历史。

Windows 交付包继续使用现有文件白名单生成，只包含程序、安装/启动脚本、说明和许可证，不包含 `.git`、测试、源码或本地状态。
