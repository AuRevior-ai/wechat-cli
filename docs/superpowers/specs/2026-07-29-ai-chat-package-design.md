# 微信 AI 资料包设计

日期：2026-07-29

## 目标

让 CLI 与 Web 都能把指定聊天和日期范围整理为可直接交给 AI 的资料包：

- 展开微信“合并转发”的逐条内容，包括嵌套转发。
- 从微信 4.1 的 `media_N.db` 读取 SILK_V3 语音，解码并在本机离线转写。
- 将图片、表情、文件、视频和语音放入 ZIP 的 `素材/` 目录。
- 在可复制文本中用稳定的相对路径引用素材，例如 `[图片：素材/20260729-124401-4-image.png]`。
- 保持现有“复制”和“复制精简信息”，并增加“下载 AI 资料包”。

## 方案比较

### 方案 A：只导出文字

实现最小，但 AI 看不到图片和表情，语音与合并转发也会丢失上下文，不满足目标。

### 方案 B：把素材转成 Base64 塞进复制文本

理论上一个文本即可传递，但体积会膨胀约三分之一，容易超过剪贴板和 AI 输入限制，也不便人工核对。

### 方案 C：ZIP 资料包（采用）

ZIP 内包含 `聊天记录.txt`、`清单.json` 和 `素材/`。文字使用相对路径指向素材，结构清楚、可复核、可重复处理，且适合上传给支持附件的 AI。

语音识别采用本地离线模型。云端 API 会上传私密聊天并要求密钥；把模型直接塞进主 EXE 又会显著放大每次交付。采用首次使用按固定 URL 下载、校验 SHA-256 后缓存的方式，兼顾隐私与交付体积。

## 数据解析

### 合并转发

微信 `appmsg/type=19` 的 `recorditem/recordinfo/datalist` 递归解析为结构化条目：

- `datatype=1`：文字。
- `datatype=2/3`：图片。
- `datatype=4`：语音。
- `datatype=5/19`：链接或应用消息。
- `datatype=8`：文件。
- `datatype=17`：嵌套合并转发，继续解析 `recordxml`。
- 其他类型保留类型号、描述和标题，避免静默丢失。

解析限制为最多 6 层、1000 条、单段 XML 4 MiB；拒绝 DTD/ENTITY。超过限制时生成明确的“内容已截断”条目，而不是递归失控。

### 语音

最新微信语音在 `message/media_N.db`：

- 用 `Name2Id.user_name` 定位会话 ID。
- 用 `chat_name_id + local_id` 为主键查询 `VoiceInfo.voice_data`，时间与服务端 ID作交叉验证。
- 原始数据保存为 `.silk`，随包提供解码后的 16 kHz 单声道 `.wav`。
- SILK 解码器随 Windows 应用交付；不依赖目标电脑安装 FFmpeg。
- sherpa-onnx Windows x64 运行组件和 Paraformer 中文 int8 模型首次使用下载到 `~/.wechat-cli/models`，每个归档都校验固定 SHA-256，安全解压后才启用。
- 转写按语音内容 SHA-256 缓存。识别失败时仍保留音频和错误说明。

语音识别结果属于机器转写，在文本和清单中明确标记，不伪装成微信原始文字。

### 图片与表情

- 图片继续读取微信 `msg/attach`，但匹配时优先使用 XML 的 `cdnthumblength` 与实际 `.dat` 大小（包括微信 4.1 的 31 字节封装头），再用时间兜底，防止同一秒多图串位。
- 微信 `.dat` 图片在写入资料包前解码为真实扩展名。微信 4.1 的 V2 图片采用 AES-128-ECB + 尾部 XOR：从运行中的 `Weixin.exe` 可写内存查找精确 16/32 位字母数字候选，只以多个 V2 密文块能解出图片魔数为成功；XOR 字节由多个 JPEG 缩略图尾标记投票获得。验证后的密钥原子写入本地配置，下次先复验再决定是否重扫。
- 标准图若为微信 `wxgf`/HEVC，资料包改用同组已解密 JPEG 缩略图，确保常见 AI 能直接读取，而不是输出占位图。
- 表情优先使用本地缓存；缺失时只允许从微信官方图片域名下载，限制重定向、内容类型和大小，并验证魔数。
- 相同 SHA-256 的素材只存一份，多条消息复用同一相对路径。

## 资料包结构

```text
会话名-20260729-20260729-AI资料包.zip
├── 聊天记录.txt
├── 清单.json
└── 素材/
    ├── 20260729-110552-116-voice.wav
    ├── 20260729-124401-4-image.png
    └── sticker-<sha256>.gif
```

`聊天记录.txt` 使用中文、UTF-8，包含会话、日期、消息总数、素材说明和按时间排列的消息。合并转发以缩进层级展示。绝对本地路径、数据库密钥和远程鉴权 URL 不写入资料包。

`清单.json` 保存资料包版本、消息结构、合并转发树、素材相对路径、SHA-256、大小、内容类型、转写状态和逐项失败。它是机器可读真值，便于后续程序继续处理。

素材文件名由日期时间、消息 ID、类型和内容哈希生成；清除 Windows 非法字符，防止 ZIP 路径穿越和跨平台解压问题。

## CLI

新增：

```text
wechat-cli ai-package "会话名" --start-time 2026-07-29 --end-time 2026-07-29 --output result.zip
```

默认：

- 导出完整日期范围内的全部消息。
- 展开合并转发。
- 收集图片、表情、文件、视频和语音。
- 对语音进行离线转写。

提供 `--no-transcribe-voice` 作为快速模式；缺少模型时正常下载并显示进度。命令最终输出 JSON，包含 ZIP 路径、消息数、素材数、转写数和失败列表，便于 Web 复用。

## Web

聊天记录页提交查询时启用媒体解析。结果区保留：

- `复制`：总结提示词 + 完整记录，素材显示为 `素材/文件名`。
- `复制精简信息`：仅范围、发言人、类型、正文、转写和素材引用。
- `下载 AI 资料包`：用当前会话与日期生成 ZIP 并下载。

资料包通过专用本地 API 生成。API 只接受白名单字段，不接受任意命令或任意输出路径；服务器在状态目录创建临时 ZIP，以一次性随机令牌下载，并按过期时间清理。网页显示“准备素材 / 下载离线模型 / 语音转写 / 打包完成”等阶段，避免用户误以为卡死。

## 错误、安全与兼容

- 单条素材、嵌套转发或转写失败不会中断整个资料包。
- 下载只允许固定 HTTPS URL，校验 SHA-256；归档解压检查目标路径必须仍在缓存目录内。
- 表情远程下载仅允许微信官方域名，限制 20 MiB 和图片魔数。
- Web 媒体读取仍限制在微信数据目录或本次资料包目录内。
- 当前完整测试套件必须继续通过；新增解析、数据库、下载校验、ZIP 安全、CLI 和 Web 测试。
- 目标为 Windows x64、微信 4.1.12.26 及同系列最新数据库布局；旧版存在文件夹语音时保留原解析兜底。
